# 规范版本治理（spec-versioning）

> 版本：2026-11-22（roadmap B7 W4，附录 A #1 P7 兼容承诺补全）。
> 定位：工作流定义规范（YAML `spec_version`）的版本治理专页——版本策略、
> 「1.x 只增不删」承诺与强制护栏机制。
> 版本语义、兼容矩阵与迁移指南主文档：[yaml-spec.md](./yaml-spec.md)
> 「版本与兼容性承诺」章（本页交叉引用，不重复矩阵表）。

## 1. 版本注册表现状

- **事实来源**：`workflow/specification_version_registry.py`
  （`SpecificationVersionRegistry`，唯一权威）。
- **已注册版本**：`"1.0"`、`"1.1"`。
- **匹配语义**：精确匹配，不做降级解析——版本高于支持上限时终止解析
  并报错提示当前支持区间（需求规格 5.1.3.2：避免用旧规则误读新版本定义）。
- **版本号语义**：语义化版本（MAJOR.MINOR）——
  - MINOR（1.x 内递增）：追加新字段、新节点类型、放宽校验规则；
  - MAJOR（1.x → 2.0）：破坏性变更（见 §3）。

## 2. 1.x 只增不删承诺（P7）

1.x 系列内向所有已发布规范版本承诺：

1. **已注册版本永不移除**：`"1.0"` / `"1.1"` 一旦注册即永久留在支持
   集合（未来 `"1.2"` 等仅以追加方式进入）。
2. **已发布字段永不删除**：既有字段不删除、不改名、不变更语义；追加
   可选字段允许（CHG-11「追加可选字段」先例：既有字段零变更）。
3. **新字段可选且默认兼容**：新增字段必须可选，解析校验为 lower-bound
   （`>=` 语义）——新样例、新节点类型自动纳入护栏，不冻结总数。

引擎侧对应义务（与承诺配套，护栏测试强制）：

- **HC-02**：`NodeType` 枚举仅追加——既有成员不删除、枚举值不变更；
- **五要素守卫**：`REQUIRED_TOP_LEVEL_FIELDS` 不得新增必备顶层字段
  （新增必备字段 = 收窄存量，禁止；放宽允许）。

## 3. 破坏性变更 = 2.0 边界

删除既有字段/节点类型、收窄既有校验规则、变更既有字段语义——一律属
破坏性变更，**只能进 2.0**，且必须附迁移指南（先例：yaml-spec.md
「迁移指南」章）。2.0 相对 1.x 不做降级解析（高于支持区间精确匹配
拒绝，同 §1 匹配语义）。

## 4. 强制机制（护栏测试）

承诺以测试强制执行，两层互补：

| 层 | 文件 | 防什么 |
|----|------|--------|
| lower-bound 自动发现 | `tests/integration/test_spec_version_compat_guard.py` | 新样例/新行为破坏既有承诺：examples/ 全量参数化可加载、每版本行为回归（节点数上限 50/200）、HC-02 枚举仅追加、五要素不收窄、未支持版本拒绝不降级 |
| 快照冻结 | `tests/unit/test_spec_version_guard_snapshot.py` | 已注册版本被删：① 注册表现存版本 ⊇ `{1.0, 1.1}` 超集断言（移除任一即失败）；② 快照内每版本在 examples/ 下仍有对应定义且全链解析通过（删光/损坏即失败） |

互补关系：前件加法安全（新增范例/新版本自动纳入、不误报），后件防删
（版本或对应范例被移除即失败）；新增版本（如未来 `"1.2"`）两件均不失败。
